Build Academy Tutor as one readable Pi 0.87.1 extension, `tutor.js`, for a hands-on lesson. Use `cards.json` as the course; each card has an id, question, answer and published source links. Read the installed official reference in `docs/extensions.md` as needed. Implement the behavior below without looking for another tutor implementation. Favor clear code that a learner can explain.

1. `/academy` starts practice. Read append-only `attempts.jsonl` when it exists; the last record per concept is current. Select overdue/due concepts first for review, then unseen concepts for learning, in course order within each group. Exclude concepts with future review dates. If none qualify, tell the learner and do not start a model turn.
2. Give the model selected cards and mode. For learning, explain briefly then ask one question (assisted). For review, ask before explaining. Assess against the card answer, offer sources when useful, handle skips without recording, and stop when finished or asked. These are model instructions, not claims of deterministic model behavior.
3. During practice expose only `read` and a custom `record_attempt` tool. Its inputs are concept, correctness (`correct`, `partial`, `incorrect`), assisted (boolean), and nonempty evidence. Reject concepts outside this session’s remaining queue, including duplicate recordings.
4. A correct unassisted answer is due 3 days later; every other assessed answer is due 1 day later. Append one JSON line with the inputs plus ISO `reviewedAt` and `dueAt`; preserve all earlier lines. Remove the accepted concept from the queue and return saved data plus remaining concept ids.
5. Keep the existing course data unchanged. Work only in this folder. Create only `tutor.js` and optionally `implementation-notes.md`. Do not install packages, access credentials or unrelated files, use network tools, or create an SDK app. Dependencies are already installed. This is one implementation attempt; write the result and briefly explain its design and limits.
